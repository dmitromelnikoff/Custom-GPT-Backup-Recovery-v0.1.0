# Кейс восстановления 250 Custom GPT — факты и хронология

**Основание:** логи пользователя, полученные при реальных запусках в авторизованном Chrome, отчёты snapshot/Knowledge. Числа относятся к тому состоянию, которое было предоставлено к **29 октября 2026 года**. Ни сами конфигурации GPT, ни файлы Knowledge в открытом репозитории не публикуются.

## Цели владельца

1. Сохранить **свои**, а не чужие Custom GPT: названия, Instructions, настройки/Actions насколько доступны, Knowledge **исходными байтами** и профильные иконки.
2. Сохранить привязку *GPT ID → file ID → размер → SHA-256 → путь → происхождение*.
3. Автоматизировать 250 GPT и 1 869 Knowledge-файлов; не скачивать тысячи файлов вручную.
4. Не заменять оригинал похожим файлом из Library/плагина/другого GPT без маркировки.
5. Не изменять архив Obsidian. Продолжать работу после частичных сбоев и не обходить защитные ограничения сервиса.
6. В итоге получить **воспроизводимый и безопасный GitHub-проект без личных данных**.

## Этапы

### A. Инвентаризация и неудачный backend-download

Создан `gpt_list_snapshot.json` с 250 GPT, 1 869 файлами Knowledge (в 177 GPT). В приватной папке сохранены метаданные GPT и извлечённые данные Instructions/Actions там, где это реально было доступно. Попытки скачать Knowledge по прямым backend/signed URL часто завершались **404 или 415**. Эти ответы нельзя исправить выдуманным endpoint'ом.

### B. Library и обнаружение несовпадающих версий

Создан поиск в ChatGPT Library: была очередь около 1 171 уникальных имён, учитывающая повторы между GPT. Для одного Markdown-документа Library вернула **40 178 байт**, а прямой скачанный из Knowledge своего GPT оригинал имел **40 366 байт**; их SHA-256 различались. В публичной версии название и отпечатки файла намеренно не раскрываются. Отличия содержательные, не просто CRLF/LF. Пользователь вручную перепроверил Library: она действительно отдавала другой экземпляр. Это запретило безусловное назначение по имени. Позднее Library UI-поиск 15 раз вернул `NOT_FOUND_UNCONFIRMED`, 16-я попытка получила 429; подтверждённых новых файлов из той очереди не было.

### C. Прямой UI-путь — ключ к успеху

Итерации v1–v4 выявили устройство редактора: сначала нужна вкладка **«Конфигурация» (`radio`)**, затем строка файла, а команда «Скачать» может оказаться **во просмотрщике/фрейме**. v5 впервые реально автоматически сохранил `05_PROBLEM_DEFINITION_METHOD.md` размером 41 892 байта с SHA-256. Затем v5 скачал 3/3 файла подряд, v6 научился переключаться по GPT, v7 — откладывать ошибки, v8 — различать общие базы, v9 — стабилизировал просмотрщик и доказал работу на нескольких GPT, v10 — временно обходить проблемные семейства, v11 — работать длительно без ручного сопровождения.

### D. Общие базы: не путать с доказанными оригиналами

Метаданные выявили **33 группы** потенциально общих исходников, **141 Knowledge-запись**. Два близких по назначению пользовательских GPT имели 10/10 общих файлов с совпадающими именами/размерами/временем создания и изменения, но **разными file ID**. У одного GPT файл выдавал 404, у другого скачивался. Подтверждённый SHA файла-донора нельзя объявлять SHA другого экземпляра без отдельной проверки. Доноры сохранялись с происхождением.

### E. Массовое скачивание

- Перед большими обходами: **72** присутствовавших на диске файла, из них часть была Library-size-only.
- Длительный проход №1: **90 GPT**, **1 339 попыток**, **1 306 новых** Knowledge. Безопасная остановка при **HTTP 403** на одном из запросов просмотра/скачивания. Лог не доказывал, что это именно отказ доступа к конкретному документу.
- Длительный проход №2: **87 GPT**, **382 попытки**, **339 новых** Knowledge; завершился `QUEUE_EXHAUSTED_WITH_UNRESOLVED_FILES`, а не блокировкой.
- После этого суммарно **1 717/1 869** файлов присутствовали на диске, из них **1 676** уже подтверждались прямыми receipt-хешами, а **41** было size-only.

### F. Восстановление из локальных архивов

- Ручной импорт двух найденных файлов из Obsidian/архива.
- Автопоиск по `X:\Vault\GPT_Assistents`: **34** копии.
- Сверка реальных SHA-256 девяти общих исходников и установка **41** копии в GPT.
- Проверка и установка **55** кандидатов одного семейства GPT.
- Ручной поиск и импорт **5 Markdown**.
- Импорт **11** изображений Knowledge.
- Количество на диске выросло до **1 865**. Обратите внимание: **кандидатные копии физически сохранены, но их соответствие экземплярам конкретных GPT пока не доказано**.

### G. Профильные иконки

Исправлена утилита получения аватаров GPT: v2 с более безопасным ограничением HTTP, паузами и сохранением результатов. Владелец сообщил, что **все иконки скачались**. Фактический финальный CSV иконок не был приложен к этой итоговой сверке, поэтому численное подтверждение иконок не приписывается аудиту Knowledge.

**Отсутствующие четыре Knowledge-изображения:** четыре отдельных файла PNG из разных GPT. Их имена и размеры не публикуются в публичном кейсе, поскольку относятся к приватному архиву пользователя. Полный реестр остаётся только у владельца.

Наличие иконки профиля не означает наличие одноимённого изображения Knowledge. Нельзя заявлять **100% Knowledge**, пока эти четыре записи не закрыты.

## Что известно, а что не установлено

**Известно:** 1 865 файла с ожидаемым размером; 1 676 с хешами, совпавшими с прямыми receipt'ами; успешные реальные серии загрузок; реестр отложенных ошибок; локальный архив в режиме только чтения.

**Не установлено:** побайтовая идентичность 189 кандидатных файлов Knowledge их исходным экземплярам GPT; полная воспроизводимость недокументированного snapshot bootstrap в будущих версиях сервиса; доступность всех Actions в первоначальном снимке; точное число загруженных аватаров в отсутствие финального CSV.
