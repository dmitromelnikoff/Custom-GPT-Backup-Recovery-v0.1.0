# Provenance и доказательность

**Различайте «файл есть» и «оригинал именно этого GPT подтверждён».**

| Статус | Что установлено | Что НЕ установлено |
|---|---|---|
| `DIRECT_HASH_VERIFIED` | Данные на диске совпадают с SHA-256 из записи успешного прямого скачивания своего GPT или подтверждённого ручного direct-импорта | Независимый серверный hash OpenAI не предоставлялся |
| `PRESENT_UNVERIFIED_OR_ARCHIVE_CANDIDATE` | Путь и размер соответствуют snapshot | Байтовое совпадение с target `file_id` |
| `SHARED_SOURCE_CANDIDATE` | Источник принадлежит другому GPT и имеет проверенный SHA; метаданные связанной записи похожи | Что оба GPT хранили одинаковые байты |
| `LOCAL_ARCHIVE_CANDIDATE` | Локальный файл имел проверенные имя, размер и SHA, был скопирован без изменения источника | Что копия соответствует файлу, хранящемуся на сервере GPT |
| `LIBRARY_CANDIDATE` | Файл получен из Library; можно сохранить в карантине | Что он совпадает с Knowledge целевого GPT |
| `MISSING` | Файла нет по ожидаемому пути | Что он отсутствует во всех других локальных папках |

### Почему SHA-256 важен, но не всемогущ

- **Равные SHA-256** двух локально найденных файлов => их байтовое содержимое с чрезвычайно высокой степенью уверенности одинаковое.
- **Разные SHA-256** => различные байты, даже при одинаковых названиях и размерах.
- Проверка SHA донора **не доказывает**, что неизвестный экземпляр GPT равен донору.
- `file_id` — идентификатор записи в источнике. Он нужен для provenance; совпадение имени файла не отменяет различий `file_id`.
- `size_matched` — проверка размера, **не** проверка целевого SHA.
